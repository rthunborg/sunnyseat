## 2. What Went Well

- **Opt-in env-flag discipline held in every single story.** `SUNNYSEAT_VENUE_STORE` (8.2), `SUNNYSEAT_SUN_ENGINE` (8.3), `SUNNYSEAT_*_PERSISTENCE` (8.4), flipped Production-only at 8.5. The default path stayed in-memory/seed and **byte-identical**, with zero live-Supabase/Met.no dependency in CI. A 7-story data-layer rebuild landed with **no production blast radius**.
- **Adversarial code review caught real, cutover-breaking issues before they shipped:** the NaN-sort enum leak (8.2), the per-sample timeline degrade restore (8.3), the **`feedback` SELECT-grant gap** that would have silently broken `INSERT … RETURNING` at the 8.5 cutover (8.4), and the **`roof_z` safety regression** in 8.7 (caught in dev — see below).
- **Safe-direction engineering.** 8.1.1's conservative 15 m cap on height-uncertain casters errs only toward over-shadowing (never false-sunny); 8.7 deliberately *preserved* that cap by using the conservative runtime height + a ground delta rather than the raw `roof_z`.
- **Pre-ratified decisions avoided mid-dev thrash.** 8.3's four decisions (A–D) and 8.7's Option A were resolved with Rasmus at/before dev start.
- **Clean layering on shared seams.** The 8.2↔8.3 "durable attributes vs sun-engine outputs" boundary held; 8.6 (Tier-1) → 8.7 (Tier-2) layered on the same `seatingElevationM`/`computeShadowInfo` plumbing with one-line behavioural deltas.
- **Server-only boundary discipline.** `seatingArea`, `seating_elevation_m`, `ground_elevation_m`, and caster RH2000 Z were each kept server-only and explicitly asserted *never* in `toVenueData`/`VenueDataDto`.
- **Monotonic test growth** (527 → 625, none dropped) and a reusable test-infra fix (the dynamic-import mock-bypass → mock the adapter boundary), now a standing project rule.
- **Deferred-work queue hygiene worked** — items carried into target stories (R2-D2→8.2, R2-D1→8.4, the 8.2-R2/8.3-R1/8.4-R1 hardening set→8.5) and were removed on draft.

## 3. What Was Hard

- **Story grounding could not be trusted literally — the single biggest recurring risk.** Specs repeatedly asserted facts that were wrong against the live DB/code:
  - 8.1: stale on-disk artifacts + a hard-coded stale batch id that risked a no-op delete + duplicate import.
  - 8.3: the engine's `calculateVenueShadow(venueId)` targeted an incompatible PascalCase table, forcing a new geometry-first entrypoint.
  - **8.7 is the cautionary tale:** the story claimed the RPC already exposed caster Z ("just map them" — it returned 15 columns, none of them Z) **and** that `roof_z − ground_z = height_m` (false for ~1,212 height-uncertain casters). Implemented literally, it would have **resurrected the exact raw heights 8.1.1 capped** and broken AC2. The dev agent caught both only by verifying against the live DB.
- **8.1's scope had to be re-cut mid-flight.** The conservative 3.0.x filter deactivated ~1,569 real height-uncertain buildings → systematic false-sunny → AC2 carved out into the new Story 8.1.1.
- **Concurrency on the real list path** — uncapped `Promise.all` fan-out over venues (8.3) risked Met.no TOS / connection exhaustion and triggered the mock-bypass; required a concurrency cap + forecast dedupe + never-500 degrade in 8.5.
- **Test-infra flakiness** surfaced repeatedly: the concurrent dynamic-import mock bypass (8.3), a timing-dependent concurrency assertion (8.5), Playwright page-setup timeouts under parallel workers (8.5).
- **Process gap:** 8.1.1 — a story that *changed filter/activation logic* — shipped with **no adversarial code-review round** (maintainer-directed to proceed after self-verification). It's the only Epic 8 logic story that skipped the review layer.
- **Out-of-band schema management.** Every DB-touching story applied schema/data via psql or MCP `execute_sql`; the **migration ledger is empty by decision**. The `.sql` contract files are the source of truth — workable for MVP, but a latent reproducibility risk.

## 4. Key Insights

1. **Verify story grounding against live DB/code *before* implementing — don't trust the spec's "already exists / just map it."** This caught a safety-cap regression in 8.7 that a literal implementation would have shipped. Worth building an explicit "confirm grounding" step into story execution for data/contract stories.
2. **Opt-in flags + a byte-identical default path is the right shape for a high-risk data swap.** It decoupled "build + live-apply" from "go live," so the whole epic shipped to `done` with the production app untouched.
3. **The empty migration ledger is the epic's main latent debt.** Out-of-band applies worked, but before the next schema-heavy epic, consider adopting the migration ledger (or at minimum a verified apply-from-`.sql` runbook) so the live schema is reproducible from version control.
4. **Adversarial review pays for itself at a cutover boundary.** Three of the issues it caught (feedback grant, NaN-sort, roof_z) would have been silent until production. That argues *against* skipping the review layer on logic stories (cf. 8.1.1).
