## 2. What Went Well

- **Root-cause triage held for the whole epic.** All 11 stories trace cleanly to one of the 5 diagnosed root causes from the 2026-06-30 party-mode session; no story drifted into unrelated scope, and no new root cause was discovered mid-epic that wasn't already folded into the mobile-smoke-test addendum.
- **Cross-story "clobber traps" were anticipated in create-story and held in dev-story.** 9.5→9.6's locate-reliability wiring (aria-busy/data-locate-state/pulse) was explicitly flagged as at-risk during 9.6's create-story and was correctly *relocated* (not deleted) onto the surviving top-bar control in dev-story. Same pattern for 9.7's tag-filter de-dupe invariant (nav chips vs MapView list/pins) — caught as a real fetch-hygiene regression *inside* 9.7 and fixed with a locked invariant test before it could surface later.
- **"No dead tiles" principle was enforced against the epic's own raison d'être.** 9.8 explicitly declined to reproduce the exact defect class (Instagram/Snapchat brand tiles with no real web share-intent) the epic exists to eliminate, rather than blindly porting the reference design.
- **A genuine latent production bug was found and fixed, not just guarded.** 9.10's Task 3 root-caused the live "type number, found null" MapLibre console warning to an unguarded `project()` call reachable via the `?venue=<slug>` deep-link with a null-coordinate venue, and shipped a real fix (`hasValidVenueLocation` guard) with 3 targeted tests — this was cross-story verification work surfacing a bug none of 9.0–9.9 introduced or caught.
- **Host-tooling workaround was documented once and reused epic-wide.** The Windows `/tmp` visual-validate breakage (discovered in 9.2) was captured with its manual-affordance fix and cited by every subsequent frontend story instead of being rediscovered per-story.
- **Deferred-work queue hygiene stayed tight under real volume.** Multiple items were closed *inside* the epic rather than parked: the 9.5 honest-distance-label defer closed in 9.9 Task 3; the 9.9 planner-clearance conditional closed in 9.10's live-DOM assertion; the 7.3 SW stale-tab defer was retired by 9.5's controllerchange-reload work; the stale-references cascade was consolidated into one maintainer action instead of 6 scattered ones.
- **Byte-identical/invariant discipline on the performance stories.** 9.3's dedupe of the double `get_buildings_near_point` RPC call was verified as a byte-identical output guard (not a "close enough" rebaseline), and 9.4's query-hygiene decisions explicitly froze the staleTime/bucket/query-key contract other stories must not touch.

## 3. What Was Hard

- **The stale reference-PNG rebaseline cascade compounded across six stories (9.1/9.5/9.6/9.7/9.8/9.9) into one epic-close-out blocker.** Every removal/rework story correctly declined to self-bless a new reference (dev agents are forbidden from editing them), but the result is that Epic 9 cannot truthfully claim a green visual gate until a maintainer runs one consolidated rebaseline pass (map-primary, map-with-selected-venue, venue-detail at mobile+desktop, plus two entirely missing references — the 9.8 desktop share modal and the 9.5 location dot). This is structurally correct behavior per-story but is a real, unresolved cost at the epic boundary.
- **Documentation/reality drift showed up repeatedly and had to be caught by grounding checks, not trusted.** architecture.md referenced a non-existent `LocationPermission.tsx` sibling (9.5); a 9.5 deferred-work note pointed at a stale `custom/venue/` path for a component that actually lives at `composed/venue/` (9.9); a 9.5 file-impact map wrongly claimed no `[locale]/layout.tsx` existed, when it did — and that exact file is what made the onboarding dead-click window a *real* bug, not cosmetic (Tier-A review caught it). Each was individually recoverable, but the pattern recurred enough to be a standing risk for this codebase's planning docs.
- **Platform/tooling landmines cost real rework inside stories.** Next 16 renamed the Edge middleware convention `middleware.ts` → `proxy.ts` (hard build error if both exist) — 9.3 had planned around the old name and had to integrate into the existing `proxy.ts`. Edge runtime's ban on `node:net` forced swapping `isIP` for a hand-rolled regex mid-story. A stale Turbopack CSS cache silently served the pre-fix gradient after a correct edit (9.2), requiring a full `.next` wipe to even verify the fix.
- **The host visual-validation gate is structurally broken on this environment.** `.claude/scripts/visual-validate.sh` writes to a `/tmp` path the Windows-native Playwright binary cannot use, so *every* frontend story in the epic (9.1, 9.2, 9.5, 9.6, 9.7, 9.8, 9.9) had to fall back to a documented manual affordance instead of the automated gate. Workable, but it means no story in this epic got a fully automated visual pass.
- **ATDD red-phase scaffolds shipped stale metadata once they went green.** The `(RED)` describe-block naming + "STATUS: WILL FAIL" docstring convention is correct at scaffold-authoring time, but nothing in the workflow strips it once a scaffold is un-skipped into a live passing guard — test-review caught this epic-wide (92/100, one convention gap) rather than it being cleaned up story-by-story.
- **sprint-status.yaml drifted from the story-file source of truth.** `9-0` is still recorded as `ready-for-dev` in the machine-readable tracker while its story file has carried `Status: review` (with completed, green work) since dev-story finished — a truthful-status gap flagged at the trace gate and left for the epic-boundary batch-flip to correct.

## 4. Key Insights

1. **A shared "clobber trap" ledger between adjacent stories (9.5↔9.6, 9.4↔9.7) is what prevented silent regressions, not luck.** When create-story explicitly names which surviving story owns a piece of cross-cutting behavior, dev-story reliably relocates rather than deletes it. Worth continuing as standard practice for any epic with UI-consolidation stories adjacent to UI-behavior stories.
2. **Removal/rework stories structurally invert the visual gate** — a *correct* de-bloat or rework implementation necessarily fails comparison against a reference PNG of the old design. This is now well-understood epic-wide, but it means "visual gate: PASS" cannot be epic-exit criteria without a maintainer rebaseline pass; that pass should be scheduled as its own step, not assumed to happen incidentally.
3. **File-impact maps and architecture-doc component references must be verified against the tree at create-story time, not trusted at face value.** Three separate instances this epic (missing `[locale]/layout.tsx` awareness, phantom `LocationPermission.tsx`, stale `custom/venue/` path) show this is a systemic gap in planning-doc freshness, not a one-off.
4. **Platform-version landmines (Next 16 `proxy.ts` rename, Edge `node:net` ban) are cheap to hit and expensive to discover mid-story.** A quick "check the current framework's Edge/middleware conventions before assuming a doc-remembered API" step at create-story time for any Edge/middleware-touching story would have caught the 9.3 rework before dev-story.
5. **The Windows-host visual-validate `/tmp` bug is now a known, epic-wide tax, not a one-story blocker** — every future frontend story on this host should budget for the manual affordance from the start rather than attempting (and failing) the automated path first.
