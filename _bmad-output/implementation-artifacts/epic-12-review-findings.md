# Epic 12 Integration Review - Triaged Findings

- **Epic:** 12 - sunlight trust, persistence, media, and search integration.
- **Date:** 2026-08-07.
- **Inputs:** 2 reviewers x 15 chunks x 3 lenses, the whole-epic security review, the whole-epic diff, Story 12.1-12.14 files, and Epic 12 planning/spec artifacts.
- **Security:** 1 Medium finding, retained as Patch.

Triage normalized and deduplicated raw findings across reviewers and lenses. Per-story review findings that were already fixed in Story 12 review loops were dismissed as handled elsewhere. Only surviving findings are listed below. All survivors are Patch findings; no Decision or Defer findings survived triage.

### Review Findings

- [x] [Review][Patch][High] Feedback POST trusts client-supplied prediction evidence instead of verifying against the current server-owned venue prediction (`nextjs-app/app/api/venues/[slug]/feedback/route.ts:137`) - the route accepts self-consistent client evidence hashes/verdicts/weather state, so fabricated or stale evidence can pollute the feedback accuracy loop.
- [x] [Review][Patch][Med] Feedback evidence accepts non-canonical geometry hash versions (`nextjs-app/app/api/venues/[slug]/feedback/route.ts:25`, `nextjs-app/lib/services/feedback-accuracy-report.ts:4`, `nextjs-app/supabase/migrations/20260806190000_feedback_accuracy_loop_evidence.sql:39`) - only the current canonical `g1:<64 lowercase hex>` shape should be accepted by the API, report parser, and database constraint.
- [x] [Review][Patch][Med] Feedback wrong-window reporting bins representative submissions by UTC instead of Stockholm local time (`nextjs-app/lib/services/feedback-accuracy-report.ts:520`) - venue feedback around day boundaries can be attributed to the wrong local reporting window.
- [x] [Review][Patch][High] The combined sun geometry/weather workflow runs the heavy geometry job on every scheduled weather refresh (`.github/workflows/sun-geometry-and-weather.yml`) - schedule events are not gated by the cron expression, so 15-minute weather runs also trigger geometry precompute.
- [x] [Review][Patch][Med] Weather snapshot refresh is scheduled every 15 minutes despite the Epic 12 current-weather freshness contract requiring a 5-minute cadence (`.github/workflows/sun-geometry-and-weather.yml`) - persisted weather can be older than the architecture/spec freshness budget before any runtime lookup occurs.
- [x] [Review][Patch][High] Public `weatherBucket` query parameters let callers bypass current weather gating (`nextjs-app/app/api/venues/route.ts:298`, `nextjs-app/app/api/venues/[slug]/route.ts:100`, `nextjs-app/lib/services/weather-snapshots.ts:224`) - routes pass caller-provided buckets while the writer only maintains the server-owned current bucket.
- [x] [Review][Patch][High] Persisted weather snapshots gate only exact forecast minutes, leaving most 15-minute planner steps weather-unknown (`nextjs-app/lib/services/weather-snapshots.ts:111`) - provider `validAt` timestamps are stored directly rather than mapped with nearest-valid semantics or materialized to the planner grid.
- [x] [Review][Patch][Med] Geometry input hashes are computed over a different caster radius/set than runtime projection (`nextjs-app/lib/services/sun-geometry-repository.ts:440`) - cache/evidence identity can remain stable while the actual shadow caster set changes.
- [x] [Review][Patch][Med] Geometry precompute lease claiming has race and false-success paths (`nextjs-app/supabase/migrations/20260718193000_persist_sun_geometry_series_and_weather_snapshots.sql:259`, `nextjs-app/scripts/precompute-sun-geometry.ts:50`) - concurrent runners can believe work was claimed or completed when the database lease did not establish that ownership.
- [x] [Review][Patch][High] Pre-hydration onboarding clicks can be dropped (`nextjs-app/components/custom/onboarding/OnboardingGate.tsx:241`) - the server-rendered affordance is clickable before the client handler/guard is ready, so an early dismiss/continue tap can disappear.
- [x] [Review][Patch][Med] Forced `_date`/`_time` routes can fire an initial live planner fetch before forced-state synchronization (`nextjs-app/app/AppContextProviders.tsx:86`, `nextjs-app/lib/contexts/TimeContext.tsx:254`) - deterministic visual/dev routes can briefly exercise the wrong live query key before the forced planner state lands.
- [x] [Review][Patch][Med] Reduced-motion users still receive the first-frame onboarding fade/slide (`nextjs-app/components/custom/onboarding/OnboardingScreen.tsx:142`) - `initial` motion props still animate on mount even when `prefers-reduced-motion` should suppress the transition.
- [x] [Review][Patch][Med] Dev venue editor loopback authorization trusts spoofable Host/missing-Origin requests (`nextjs-app/lib/services/dev-venue-editor-guard.ts:43`) - with dev admin and service-role credentials enabled, an exposed dev server can be coerced into accepting editor writes by supplying loopback-looking headers.
- [x] [Review][Patch][Med] Dev-editor UI entry activates without the required `SUNNYSEAT_ADMIN=dev` gate (`nextjs-app/components/custom/map/MapViewDynamic.tsx:52`, `nextjs-app/components/custom/dev/DevVenueEditor.tsx:39`) - the client probes and opens editor affordances even when the server-side editor route is intentionally disabled.
- [x] [Review][Patch][Med] Dev editor pin dragging can leave the Gothenburg bounds and enter an unsaveable state (`nextjs-app/components/custom/dev/DevVenueEditor.tsx`) - the drag UI does not enforce the same bounds as the save contract.
- [x] [Review][Patch][Med] Dev editor rendition verification uses substring search plus `limit 1`, making valid `card.webp`/`hero.webp` checks nondeterministic (`nextjs-app/lib/services/dev-venue-editor-store.ts:1279`) - a single matching object can hide the sibling rendition and falsely fail complete media sets.
- [x] [Review][Patch][Med] Deleted venues are no longer filtered from public resolver and precompute targeting (`nextjs-app/lib/services/venue-store.ts`, `nextjs-app/lib/services/sun-geometry-precompute.ts`) - public reads still guard `hidden`, but the restored paths omit the `deleted_at` filter.
- [x] [Review][Patch][Med] Mobile bottom-sheet max-row calculation can collapse a populated sheet to handle-only (`nextjs-app/components/custom/sheets/MobileBottomSheet.tsx`) - `computeMaxVisibleRows` can return zero and that value is reused when seeding/reopening the sheet.
- [x] [Review][Patch][Med] Same-slug placeholder reuse can show stale venue-detail content after planner or location changes (`nextjs-app/hooks/queries/venue-detail-query-options.ts`) - placeholder data is retained by slug while the selected planner/location context has changed.
- [x] [Review][Patch][High] Venue-detail prefetch cancellation/cooldown can disable warming for the rest of a `MapView` session (`nextjs-app/hooks/queries/useVenueDetailPrefetch.ts`) - abort/cooldown state is not scoped tightly enough to the failed target, so later valid prefetches can be suppressed.
- [x] [Review][Patch][High] Late-evening "live now" can label stale last-planner-step data as current (`nextjs-app/lib/contexts/TimeContext.tsx:1580`, `nextjs-app/lib/services/sun-geometry-repository.ts:1633`) - after planner end, the live/current path can fall back to the last persisted step instead of reporting unavailable/non-current data.
- [x] [Review][Patch][Med] The coach dialog sets `aria-modal` without making the rest of the app inert or hidden to assistive tech (`nextjs-app/components/custom/coach/FirstRunCoachMarkGuide.tsx`) - screen-reader users can still encounter background content while the modal claims modality.
- [x] [Review][Patch][Med] Coach guide progress text hardcodes the full step count even when anchors are skipped (`nextjs-app/components/custom/coach/FirstRunCoachMarkGuide.tsx:196`) - the visible/SR progress can announce nonexistent steps on layouts where some targets are absent.
- [x] [Review][Patch][Med] Coach guide can persist "seen" when the active target disappears before the user completes or skips the guide (`nextjs-app/components/custom/coach/FirstRunCoachMarkGuide.tsx`) - responsive target loss can mark onboarding as complete without an explicit user completion path.
- [x] [Review][Patch][Med] Venue media docs/tests reference `scripts/upload-venue-media.mjs`, but the diff does not add the script (`nextjs-app/docs/venue-media.md`, `nextjs-app/test/unit/story-12-12-storage-upload-and-policy.atdd.test.ts`) - the documented upload path and ATDD contract cannot be executed from the shipped tree.
- [x] [Review][Patch][Med] Forced photo-loaded visual state bypasses the managed Storage contract with an inline WebP data URL (`nextjs-app/components/custom/venue/forced-venue-detail.ts:1`) - the deterministic photo-loaded state does not exercise Supabase Storage URLs, rendition paths, or fallback semantics.
- [x] [Review][Patch][Med] Venue media storage policy regression coverage is too narrow for `public` and too broad for service-role scoped policies (`nextjs-app/test/unit/story-12-12-storage-upload-and-policy.atdd.test.ts:117`, `nextjs-app/supabase/migrations/20260719000000_venue_media_storage.sql`) - prior browser-write policies can survive while the guard still passes, and legitimate service-role policy scoping can be over-rejected.
- [x] [Review][Patch][Med] Playwright override parsing can break the required a11y gate before tests run (`nextjs-app/playwright.config.ts:1`) - config-time argv parsing is brittle enough that supported project overrides can fail the gate setup rather than the tests.
- [x] [Review][Patch][High] Closed exact-name search can be starved before client retention by the server candidate cap (`nextjs-app/app/api/venues/route.ts:90`, `nextjs-app/components/custom/search/VenueSearchShell.tsx:100`) - closed exact matches can be sliced out before the client rescue path sees them.
- [x] [Review][Patch][Med] Closed exact-name selection leaves the previous pin/preview selection alive behind the closed detail route (`nextjs-app/components/custom/search/VenueSearchShell.tsx:124`, `nextjs-app/components/custom/map/MapView.tsx:895`) - navigating to a closed exact-match detail can leave stale map selection state visible underneath.
- [x] [Review][Patch][High] Venue detail selected-instant fallback hardcodes `2026-05-20` (`nextjs-app/components/composed/venue/VenueDetailContent.tsx:376`) - missing selected-instant data can silently render against a fixed historical date instead of the requested planner instant.
- [x] [Review][Patch][Med] Future-date planner E2E no longer proves the date change preserved the pre-click time (`nextjs-app/test/e2e/map-primary.spec.ts:654`) - the collector/assertion can pass while the regression it is meant to guard is no longer exercised.
