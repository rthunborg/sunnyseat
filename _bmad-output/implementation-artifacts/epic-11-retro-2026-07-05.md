## 2. What Went Well

- **The epic thesis — "REMOVE the fetch, don't dampen it" — was stated once (11.1) and then genuinely held for eight stories.** Epics 9 and 10 had each landed a real caching/debounce win (the sun-engine cache, `useDeferredValue`) yet the user-visible stall survived because time stayed in the query key. This epic named that pattern explicitly as its own root cause and built the fix at the actual seam (decouple time from the query key entirely, derive everything client-side from a cached day-series) rather than adding another layer of damping. Every later story (11.2's slider commit, 11.3's chip filter, 11.4's per-time quick-info fields) explicitly checked "does this reintroduce time into the key?" and the answer stayed no all the way through 11.8's final confirmation.
- **A real gesture-physics bug was found and root-caused, not papered over, in two independent places.** 11.2 discovered `@use-gesture`'s `direction` reads 0 at pointer/touch-up, so a release-direction decision based on instantaneous direction silently failed; 11.3 hit the *same* bug independently in the sheet's four-snap logic and applied the same fix (derive release direction from accumulated movement sign). Both diagnoses happened via real-touch e2e (CDP `Input.dispatchTouchEvent`), which is exactly the class of defect an emulated mouse-drag would have missed — the epic's own thesis about visual/interaction gates justified itself in-run.
- **The "no-fabrication" discipline held across every content and data change.** 11.4's opening-hours field renders nothing when absent rather than a fabricated fallback; 11.6 replaced a `?? '22:00'` stand-in badge with an honest omit-when-absent badge (closing the exact class of bug the epic was hunting); 11.1's day-series never invents a value outside the parity guardrail. This is the same principle that shaped Epic 10's "unknown ≠ 0" discipline, now applied to UI content rather than weather signals.
- **Three epics of genuinely-scheduled-but-never-executed hygiene debt were finally closed in one story (11.7) without becoming a scope-creep magnet.** The `vercel.json` lightningcss swallow and the `.gitattributes` EOL-normalization gap had been carried from Epic 8 through Epic 10 (three retro action items, re-deferred each time); 11.7 fixed both with static proof (an injected `ETARGET` failure demonstrating the old chain swallowed it and the new one doesn't) rather than requiring a live deploy, and scoped the EOL fix narrowly (source extensions only, explicit `.log`/binary exclusions, renormalization kept in its own commit) rather than a destructive blanket sweep.
- **The consolidated reference-PNG rebaseline (deferred across Epics 9, 10, and every Epic-11 story) was finally executed as a single, well-organized pass (11.7) instead of continuing to compound.** 12 screen pairs were captured, verified in-DOM before staging, and documented in one `REBASELINE-LOG.md` entry — and when the Tier-A review caught a genuine defect in that capture (two screens staged byte-identical), it was root-caused and fixed in the same story rather than shipped as "close enough."
- **The Tier-B integration review caught and fixed real cross-story issues that no single story's own review could have found**, including a stale CI-invariant test (a confidence-copy regex in an *Epic 10* e2e spec that 11.4's own review missed because it only ran vitest, not that particular e2e file) and a flaky real-touch tap that was silently masked by `retries:2` in CI. Both were root-caused and hardened in-run by 11.8 rather than left as "known flaky."
- **The epic consistently distinguished "dev-blessable" from "maintainer-blessable" evidence and never blurred the line**, even under pressure to look "more done": every new visual state across 11.1–11.6 was explicitly handed to 11.7's consolidated rebaseline rather than self-blessed piecemeal, and 11.8's three remaining live/device/PNG-blessing items were consolidated into one clearly-labeled post-merge protocol instead of three separate vague TODOs.

## 3. What Was Hard

- **A three-way (dev-notes vs. actual code vs. reference-design) mismatch surfaced in 11.6's "keep the peak/best-window helpers" guidance.** The story instructions assumed the peak-time subtitle lived in the detail header and should survive the "Soltider idag" section removal; the actual code had it structurally inside the removed section, and the reference design has no such subtitle at all. The dev agent correctly treated the verbatim AC text + reference design as authoritative over the story's own narrative guidance and pruned the dead helpers — a defensible call, but it is the second epic in a row (after Epic 10's code-location misreads) where a story's prose diverged from the code it described at the line-number level, which is a signal that dev-notes line-number references need a freshness check closer to drafting time.
- **A stale cross-epic test was found only by a full-suite sweep, not by any per-story review.** 11.4 removed the visible "Säkerhet: NN%" confidence chip from the quick-info card, which broke an *Epic 10* e2e assertion (`epic-10-weather-matrix.spec.ts`'s `CONFIDENCE_BADGE_COPY` regex) that 11.4's own code review never ran (it validated with vitest only). This is exactly the "shipped-but-insufficient" pattern the epic exists to kill, just at the meta-level of test suites instead of product code — a regex tied to a specific rendered string silently went stale the moment the string moved to sr-only-only, and nothing caught it until 11.8's mandated full e2e sweep.
- **The AC3 "centered per the reference" instruction for the Omdömen section directly contradicted the literal reference JSX** (which is left-aligned), and the dev correctly prioritized the maintainer's explicit prose over the stale reference file — but this means the reference design asset itself is now known-stale for that one section, a discrepancy that only gets reconciled at the 11.7 rebaseline (i.e., a design-asset drift that traveled two stories before anyone with rebaseline authority looked at it).
- **A genuinely serious defect (a byte-identical reference-PNG pair) was carried forward silently across the *previous* commit before this epic's own review caught it.** 11.7's Tier-A review found `mobile/map-primary.png` and `mobile/map-panel-venues.png` staged as literally the same file (same git blob, same md5) — and confirmed the *prior committed* pair was also identical, meaning this specific defect had been sitting in the reference set undetected since before Epic 11 touched it. The root cause (both routes default to the sheet's `mid` snap state, so a naive capture without a state assertion produces the same pixels) is now fixed with a distinctness check, but the fact it survived at least one prior rebaseline pass is a sobering data point about how easy it is for a capture recipe's "individually-in-state" check to miss "collectively-indistinguishable."
- **The epic's touch-gesture testing infrastructure had to be built essentially from scratch under real time pressure**, and even after landing, needed a second hardening pass: 11.2 added the `touch` Playwright project and wired it into CI only after a Tier-A review caught "added a project, forgot the CI wiring" (a pattern that had already bitten in Epic 10's context per the retro-notes); then 11.8's own mandated sweep found a *second* instance of exactly the same failure mode two stories later — a genuinely flaky real-touch tap that only stayed "green" in CI because of a blanket `retries:2`, which is precisely the kind of fragility the epic's anti-"shipped-but-insufficient" thesis was built to surface, and it took the epic's own final verification story to catch it in its own infrastructure.

## 4. Key Insights

1. **Naming the anti-pattern explicitly at epic kickoff ("REMOVE the fetch, don't dampen it") and repeating it in every subsequent story's Dev Notes was the single highest-leverage move of the epic.** Unlike Epic 10's two-signal invariant (which needed re-derivation each story), this epic's thesis was restated verbatim story-to-story from the retro-notes, which meant every dev pass could self-check against a fixed, unambiguous bar ("does a settled scrub still fetch? yes = FAIL") instead of a vaguer "make it faster" goal that a caching layer could satisfy without fixing the root cause.
2. **A full-suite / cross-epic sweep is necessary, not optional, before calling a UI-removal story done — and it must include e2e, not just vitest.** Two separate epic-11 stories (11.4 removing the visible confidence line; 11.5 clashing with 11.4's already-removed ETA label) produced stale assertions in *other* epics' or *other* stories' e2e specs that no per-story review surfaced, because per-story review ran only the fast unit/component suite. The lesson from Epic 10's retro ("run the full e2e suite, not just the one you touched") was explicitly re-learned here at a slightly different failure mode (removed a rendered string → stale regex in an unrelated epic's spec) and this time was caught only because 11.8 mandated a full sweep as its own deliverable, not as an incidental side effect.
3. **A capture/verification recipe that checks "is this screen correctly in-state" is not the same guarantee as "are these two screens distinguishable from each other" — both checks are needed for any reference-PNG rebaseline.** The byte-identical `map-primary`/`map-panel-venues` defect passed an individual-state check (each route rendered its own correct DOM state) but failed a pairwise-distinctness check nobody was running, and it had silently survived at least one prior rebaseline. Future rebaseline passes (in this project or any project with a reference-PNG gate) should assert pairwise distinctness across the full staged set, not just per-screen correctness.
4. **Real-device/real-touch testing infrastructure needs its own "is this actually wired in and not flaky" audit as a standing practice, because it fails silently in two different ways.** It can fail by omission (a new Playwright project never gets invoked by CI, so a hard gate is dormant-green — caught twice, once in 11.2 by its own review, once again structurally in 11.8 confirming the fix held) or by false-positive masking (a flaky assertion stays "green" in CI only because of a blanket retry count, hiding the exact fragility a feature was built to fix — caught once, in 11.8's own infrastructure, by the epic's own final verification pass). Both failure modes are invisible to a single green CI run; only a dedicated "audit the gate's own wiring" pass (which 11.8 explicitly performed, and which now has its own config-contract vitest guards) catches them.
5. **A story's Dev Notes narrative guidance (line numbers, "keep X because Y") can go stale relative to the actual code by the time dev-story executes, and the correct resolution order is: verbatim AC text and the reference design outrank the story's own prose.** This happened twice in this epic (11.6's peak/best-window helper guidance; 11.1's touch-project reason strings later found stale in 11.8) and both times the dev agent correctly treated the AC/reference as authoritative rather than mechanically following stale prose — but it argues for tightening the create-story practice of re-verifying line-number references immediately before handoff, especially for stories drafted several stories deep into a sequential epic where prior stories have already reshaped the files being described.

### What 11.9 Delivered

- **AC1 — auto-assigning `text` PK:** kept the `text` primary key (preserving the free-text `reviews.venue_id`/`feedback.venue_id` joins) but added a sequence-backed DB default (`venues_id_seq` → `nextval(...)::text`) so a data author no longer hand-picks an id. - **AC2 — per-weekday `opening_hours`:** replaced the single pre-localized `{display, closesAt}` jsonb with a per-weekday structure (numeric ISO weekday keys, `null`/missing = closed, `close < open` = past-midnight). - **A second review round was needed to fully align documentation with reality:** the four new ATDD scaffold files still carried stale "RED PHASE / .skip'd" header comments after being un-skipped and wired to the real implementation — a smaller instance of the same "narrative drifts from code" pattern the main epic retro flagged as Key Insight 5, now recurring in test-file headers rather than story Dev Notes.

The maintainer adjudicated this as won't-fix (it's an honest absence-signal, not a fabricated time, and predates this story) — a good example of the review process correctly distinguishing "technically imprecise AC wording" from "actual dishonesty," but it means AC2's plain-language claim is slightly broader than what shipped.

### Lessons

1. **Supabase-MCP-unavailable → Docker-psql fallback is now a proven, repeatable pattern, not a one-off workaround.** Any future story that must apply a live migration should plan for the possibility of the MCP OAuth session not being active in a delegate context and should verify the Docker-psql credentials/path are current *before* migration day, rather than discovering the gap mid-story.
2. **Post-epic-end NFR-delta re-verification proved genuinely valuable rather than being a formality.** 11.9 was the epic's first post-epic-end NFR-surface expansion (a live production-DB migration folded in from a dissolved draft epic) — re-running the NFR delta instead of trusting the epic's already-frozen end-of-epic PASS caught that live-DB posture (RLS/deny-by-default) is only verifiable against the running database, not against source code alone. This argues for always re-running a targeted NFR check whenever a "final" story touches infrastructure the frozen gate never actually inspected.
3. **The "dissolve a draft epic into a story" pattern worked cleanly this time and is worth reusing when a draft epic turns out to be a single cohesive unit of work that shares an epic's branch/sequencing rather than needing its own PR/lifecycle.** The key ingredients that made it low-risk here: the adopted story had no hard code dependency on the epic's other stories (only a documented, consciously-reconciled soft interaction via the deferred-work queue), it inherited and correctly applied the epic's already-ratified constraints (never-fabricate, no-self-blessing, EOL hygiene) rather than re-litigating them, and the sprint-status note recorded the dissolution explicitly (traceable) rather than silently renumbering.
4. **A no-op or vacuously-passing test guard can slip past drafting and only be caught by review — this is a recurring shape (see also the epic-main retro's "gate wiring can be dormant-green" and "retry-masked flake" findings) and argues for a lightweight drafting-time checklist item: "for every AC-guarding test, ask what happens if the code regresses — does the test's OWN structure guarantee it would fail?"** rather than relying on review to catch it every time.
5. **Stale documentation-vs-code drift is not limited to story Dev Notes (as flagged in the main epic retro's Key Insight 5) — it also recurs in test-file header comments** (the RED-phase-vs-green-and-un-skipped ATDD headers here). Any story that un-skips a red-phase scaffold should update that file's own header comment in the same commit, not leave it for a later review round to flag.
