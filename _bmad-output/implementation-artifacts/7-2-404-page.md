# Story 7.2: 404 Page

Status: review

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a **user**,
I want a friendly dead-end page that redirects me back to the map,
so that I'm never stuck on an invalid URL.

## Context

Second story of **Epic 7 "Polish & Platform"**. Replaces the current Swedish-stub `app/not-found.tsx` with the designed 404 screen (amber "?" pin, heading, in-app CTA back to the map), fully internationalized.

> **⚠️ i18n-context nuance (the crux of this story).** The current `app/not-found.tsx` lives at the **app root, OUTSIDE the `[locale]` segment**, so it renders OUTSIDE the `NextIntlClientProvider` boundary opened in `app/[locale]/layout.tsx:27` and **cannot call `useTranslations` as-is**. Story 1.1 shipped it as a hardcoded-Swedish stub explicitly deferring i18n to this story. The dev must make the 404 copy come from `next-intl` keys AND render inside a provider — e.g. render the 404 body in a client component wrapped with its own `NextIntlClientProvider` (messages loaded for the active/`defaultLocale`), or move the not-found into the `[locale]` segment. Pick the approach that keeps the global unmatched-route 404 working. [Source: codebase — `app/not-found.tsx`, `app/[locale]/layout.tsx:27`; epics.md:2079]

## Acceptance Criteria

> ACs are verbatim from `epics.md` → Story 7.2 (BDD form). The Design Gate Criteria below are part of the definition of done for this frontend/new-screen story.

**AC1 — Mobile layout.**
**Given** a user navigates to a non-existent route
**When** the 404 page renders on mobile
**Then** it displays:
- "SunnySeat" logo top-left
- Centred content: amber pin icon with "?" inside (rounded square background, `color-amber-gold`)
- "Den här platsen hittades inte" heading (`text-display-xl`, centred)
- "Hitta soliga platser nu →" in-app navigation CTA to the map (full-width, `gradient-route-button` styling — a plain navigation link/button, **not** the Story 3.1 routing `RouteButton`, which builds native-maps directions URLs)

**AC2 — Desktop layout.**
**Given** the 404 page renders on desktop
**When** viewport >= 1024px
**Then** DesktopNavBar is visible at top and content is centred in viewport
**And** CTA button is auto-width (not full-width)

**AC3 — Icon float.**
**Given** the amber pin icon is displayed
**When** the page renders
**Then** the icon has a subtle float animation (translateY ±4px, 2s loop, ease-in-out) adding life to the static page

**AC4 — CTA navigation.**
**Given** the user taps the CTA
**When** "Hitta soliga platser nu →" is clicked
**Then** the app navigates to the map (300ms fade transition)

**AC5 — Reduced motion.**
**Given** `prefers-reduced-motion` is enabled
**When** the page renders
**Then** no float animation on the icon

**AC6 — i18n.**
**Given** all 404 text uses i18n keys
**When** the locale is Swedish or English
**Then** heading and CTA text render in the correct language

### Design Gate Criteria

(Verbatim from epics.md → Story 7.2.)

- **Visual:** Matches active visual reference `not-found`; if the MVP bundle lacks this state, use the logged curated reference

### Completion Notes List

- **The i18n crux (Task 2).** The gate route `/__sunnyseat-invalid` makes `app/[locale]/layout.tsx` fail `hasLocale` and call `notFound()`, which bubbles to the **root** `app/not-found.tsx` (a layout's own `notFound()` renders the parent boundary). So the root not-found — OUTSIDE the `[locale]` `NextIntlClientProvider` — is the single 404 boundary for the whole app, and relocating into `[locale]` would NOT cover the gate route. `app/not-found.tsx` is now an async Server Component that resolves the active locale + messages via `next-intl/server` (`getLocale`/`getMessages`, the same request config that powers `<html lang>`) and opens its own `NextIntlClientProvider` around the client `NotFoundPage`, so all copy is `common.notFound.*` keys (AC6). Verified against a genuinely invalid URL, not just a `_state` route.
- **Component (`components/custom/NotFoundPage.tsx`).** AC1: wordmark top-left (mobile) / in the navbar (desktop); centred amber-gold (`color-amber-gold`) rounded-square pin tile with a decorative `aria-hidden` "?" map-pin SVG + soft `gradient-sun-burst-warm` glow; `text-display-xl` heading. AC4 CTA: a locale-aware `<Link href="/">` styled with `gradient-route-button` (NOT the routing `RouteButton`), full-width on mobile / `lg:w-auto` on desktop; on a plain primary click it fades the page out (`animate(..., { duration: DURATION_SLOW_S=0.3, ease: EASE_EXIT })`) then `router.push('/')` — modified clicks and the no-JS path keep the link's default navigation.
- **Animation (Task 5).** AC3 pin float = Motion `motion.div` `y: [0,-4,0,4,0]`, `duration: 2`, `ease: EASE_DEFAULT ('easeInOut')`, `repeat: Infinity`. AC5: gated by `useReducedMotion() ?? true` (static-first paint, no flash; same convention as `VenuePin`) — under reduced motion the float prop is omitted AND the CTA fade is skipped.
- **Desktop chrome decision (AC2 / Task 3.2).** The root 404 renders outside `ResponsiveLayout`, so the desktop navbar is supplied explicitly. Per maintainer decision (Rasmus, 2026-06-26) it is a **bespoke minimal navbar** (wordmark + inert location/settings icons, no search box) rather than the live `<DesktopNavBar/>`, whose venue-search combobox depends on the map/search/time/geolocation contexts (`AppContextProviders`) that are not — and should not be — mounted on a static 404.
- **Visual rebaseline (Task 7).** The active `not-found` references were UNLOGGED legacy carryover that diverged from the ACs (mobile had no amber-gold square; desktop showed a stale full-search navbar). Both references were re-baselined from the running implementation (DPR 2, sv-SE) via the new `scripts/capture-not-found-rebaseline.mjs`, with a `REBASELINE-LOG.md` entry and an updated `capture-claude-design-refs.mjs` comment, in the same change. Visual gate PASS both viewports.
- **a11y (Task 6).** Single `<h1>`; CTA is a link with an accessible name, visible focus ring, `min-h-12` (≥44px) target; decorative pin SVG + glow are `aria-hidden`; no colour-only meaning; tokens only (no raw hex). axe gate clean.
- Scope held: no `tailwind.config.*`, no new API route / `hooks/queries`, no routing `RouteButton`, no new `_state` literal, no new i18n scope (404 copy lives in `common`).
