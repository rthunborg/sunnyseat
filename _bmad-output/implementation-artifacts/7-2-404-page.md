# Story 7.2: 404 Page

Status: ready-for-dev

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a **user**,
I want a friendly dead-end page that redirects me back to the map,
so that I'm never stuck on an invalid URL.

## Context

Second story of **Epic 7 "Polish & Platform"**. Replaces the current Swedish-stub `app/not-found.tsx` with the designed 404 screen (amber "?" pin, heading, in-app CTA back to the map), fully internationalized.

> **⚠️ i18n-context nuance (the crux of this story).** The current `app/not-found.tsx` lives at the **app root, OUTSIDE the `[locale]` segment**, so it renders OUTSIDE the `NextIntlClientProvider` boundary opened in `app/[locale]/layout.tsx:27` and **cannot call `useTranslations` as-is**. Story 1.1 shipped it as a hardcoded-Swedish stub explicitly deferring i18n to this story. The dev must make the 404 copy come from `next-intl` keys AND render inside a provider — e.g. render the 404 body in a client component wrapped with its own `NextIntlClientProvider` (messages loaded for the active/`defaultLocale`), or move the not-found into the `[locale]` segment. Pick the approach that keeps the global unmatched-route 404 working. [Source: codebase — `app/not-found.tsx`, `app/[locale]/layout.tsx:27`; epics.md:2079]

## Acceptance Criteria

> ACs are verbatim from `epics.md` → Story 7.2 (BDD form). The Design Gate Criteria below are part of the definition of done for this frontend/new-screen story.

**AC1 — Mobile layout.**
**Given** a user navigates to a non-existent route
**When** the 404 page renders on mobile
**Then** it displays:
- "SunnySeat" logo top-left
- Centred content: amber pin icon with "?" inside (rounded square background, `color-amber-gold`)
- "Den här platsen hittades inte" heading (`text-display-xl`, centred)
- "Hitta soliga platser nu →" in-app navigation CTA to the map (full-width, `gradient-route-button` styling — a plain navigation link/button, **not** the Story 3.1 routing `RouteButton`, which builds native-maps directions URLs)

**AC2 — Desktop layout.**
**Given** the 404 page renders on desktop
**When** viewport >= 1024px
**Then** DesktopNavBar is visible at top and content is centred in viewport
**And** CTA button is auto-width (not full-width)

**AC3 — Icon float.**
**Given** the amber pin icon is displayed
**When** the page renders
**Then** the icon has a subtle float animation (translateY ±4px, 2s loop, ease-in-out) adding life to the static page

**AC4 — CTA navigation.**
**Given** the user taps the CTA
**When** "Hitta soliga platser nu →" is clicked
**Then** the app navigates to the map (300ms fade transition)

**AC5 — Reduced motion.**
**Given** `prefers-reduced-motion` is enabled
**When** the page renders
**Then** no float animation on the icon

**AC6 — i18n.**
**Given** all 404 text uses i18n keys
**When** the locale is Swedish or English
**Then** heading and CTA text render in the correct language

### Design Gate Criteria

(Verbatim from epics.md → Story 7.2.)

- **Visual:** Matches active visual reference `not-found`; if the MVP bundle lacks this state, use the logged curated reference
- **Behaviour:** All interactions and states defined in UX spec §NotFoundPage are implemented
- **Animation:** Icon float (±4 px, 2 s loop) and page-exit fade (300 ms) animations match spec timings (±50 ms tolerance)
- **Visual validation:** Screenshot comparison against the active visual reference passes before QA handoff

## Dev Notes

### Tech stack (verified)
- **Next.js 16.2.2 App Router (Turbopack), React 19, Tailwind v4 (`@theme` in `globals.css`), Motion 12 (`motion/react`, NOT framer-motion), next-intl.** Run commands from `nextjs-app/`. [Source: architecture.md:131-198; AGENTS.md:9-21]

### Reuse, do not reinvent
- **CTA:** `gradient-route-button` utility on a locale-aware `<Link>` (from `@/i18n/navigation`), or `AMBER_CTA_BUTTON_CLASSNAME`. **Never** the routing `RouteButton`.
- **Reduced motion:** `useReducedMotion()` (`?? true` for static-first paint) + `motion-reduce:` classes.
- **Tokens already exist:** `color-amber-gold` (`globals.css:31`), `text-display-xl` (`globals.css:334`), `gradient-route-button` (`globals.css:191`), `EASE_DEFAULT='easeInOut'` (`lib/constants/animation.ts`).
- **Screen route for the gate:** `not-found` → `/__sunnyseat-invalid` (already in the Screen ID → Route Map; no route-map change needed). [Source: project-context.md]

### Anti-patterns to avoid
- ❌ Don't use the routing `RouteButton` for the in-app "find sunny spots" CTA (native-maps handoff).
- ❌ Don't leave hardcoded Swedish in `not-found.tsx` — copy must be i18n keys rendered inside a `NextIntlClientProvider`.
- ❌ Don't inline cubic-beziers/hex; use named easing + tokens.
- ❌ Don't give the decorative "?" pin a misleading role; mark it `aria-hidden`.
- ❌ Don't silently overwrite the `not-found` reference PNGs — verify, and log any rebaseline.

### Testing standards
- Vitest + @testing-library/react component tests; Playwright `a11y` (Desktop Chrome) for the 404 route; visual gate both viewports. No dropped tests. [Source: AGENTS.md:194-204]

- Unchanged contracts: API boundary (404 is static — no `lib/*` data imports, no API route), the `_state` forcing contract (the 404 is reached via a real invalid route / the `/__sunnyseat-invalid` gate route, not a `_state` value).
