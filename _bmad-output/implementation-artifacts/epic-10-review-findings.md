- [x] [Review][Defer][Med] Rain-gated outcome is cached for a 15-min bucket despite a ~5-min radar cadence — `computeRealSunEngineResult` returns `cacheable: buildings !== null` (`nextjs-app/lib/services/sun-engine.ts:632`) with NO near-now/rain exclusion, so a `CloudObscured`-because-raining outcome (and, symmetrically, a `Sunny` cached just before a shower) is pinned to the 15-min `SUN_COMPUTE_CACHE_TTL_MS` bucket (`nextjs-app/lib/services/sun-engine-cache.ts:40`). - [x] [Review][Patch][Med] Server-side list sort ranks `CloudObscured` by a fixed status tier and truncates high-solläge obscured venues before the client's solläge-aware re-sort can recover them [nextjs-app/app/api/venues/route.ts:66] — `SUN_STATUS_ORDER` fixes `CloudObscured:2` (below every `Partial:1`) and the route sorts by it then `.slice(0, MAX_RESULTS=50)` (`route.ts:310-317`) BEFORE the response is sent. Fix: make the server `.sort()` use the same solläge-aware `CloudObscured` rank as `getVenueSunRankForList` (percent-scaled), so the pre-slice order and the client order agree; update the stale `SUN_STATUS_ORDER` comment. Source: auditor@primary+auditor@secondary+edge@secondary.

- [ ] [Review][Defer][Low] `nearestToNowEntry` has no staleness/future cap on the selected nowcast slice, so a stale-nearest or future radar step can be trusted as "raining now" [nextjs-app/lib/weather/nowcast-service.ts:110-125] — the helper returns the entry with the minimum `|t - now|` (falling back to `timeseries[0]` when all timestamps are unparseable) with NO constraint that the chosen slice is at/before now or within a freshness window. Under normal operation the nowcast/2.0 product starts at ≈now at ~5-min cadence so the nearest entry is fresh; the concern is only reachable under a severe upstream shift (whole timeseries 40+ min off, or a degraded response whose only entries are hours away), which the `revalidate:60` HTTP TTL and the `radar!=='ok'` coverage guard (`:88`) already largely mitigate, and rain is a one-way additive gate that never gates Shaded/NoSun. Genuine-but-minor robustness gap, unrealistic trigger, bounded consequence. Defer — add a max-staleness bound (e.g. reject a selected slice more than a few minutes from now → `undefined`/unknown, non-gating) so a badly-shifted timeseries degrades to "unknown" rather than "raining now". Source: blind@primary+blind@secondary+edge@primary.

- [ ] [Review][Defer][Low] `applyCloudGate`'s `isRaining = false` default silently drops the rain signal for any future caller that forgets to thread it [nextjs-app/lib/services/sun-engine.ts (applyCloudGate signature)] — the load-bearing rain flag defaults to the "don't gate" value, so a new production caller (or a refactor of `computeRealSunEngineResult`) that omits `isRaining` compiles cleanly and silently degrades to "never rains" — a false-negative "it's sunny during rain", the single worst outcome for an honesty-first app — with zero type/compile error. The sole current caller threads it correctly (verified: rain gate is one-way/additive), so there is no live defect today; this is a latent hardening gap. Defer — make `isRaining` a required parameter and update the handful of legacy 3-arg pure-helper test call sites to pass `false` explicitly, so a future omission becomes a compile error. Source: blind@primary+blind@secondary.
