## Dev Notes

### Architecture Alignment

This story migrates the database schema from Azure PostgreSQL to Supabase while maintaining all PostGIS spatial capabilities. This is critical for preserving the spatial query functionality that SunnySeat depends on for patio search and sun calculations.

### Previous Story Dependencies

**From Story 6.1:**

- Next.js project setup with Supabase client integration
- Environment variables configured for Supabase connection

### Technical Implementation

**Database Architecture:**

- Supabase (PostgreSQL with PostGIS)
- Connection pooling via Supabase connection pooler
- Row Level Security (RLS) if needed
- Custom Postgres functions for spatial queries

**Schema Migration Approach:**

- Use Supabase SQL Editor or migration scripts
- Export schema from Azure PostgreSQL using `pg_dump --schema-only`
- Adapt schema for Supabase if needed
- Verify PostGIS functions match current usage patterns

**PostGIS Validation:**

- Test spatial queries before data migration
- Document any differences in PostGIS versions
- Verify spatial accuracy with sample queries

**Spatial Indexing:**

- GIST indexes on all geography columns
- GIST indexes on all geometry columns
- Verify spatial query performance

### Key Database Tables

**Core Tables to Migrate:**

- `venue` - Restaurant/café locations with basic metadata
- `patio` - Specific patio geometries with spatial data
- `building` - Building footprints for shadow calculations
- `sun_window` - Precomputed sun exposure time windows
- `weather_slice` - Weather data for confidence calculations
- `feedback` - User accuracy feedback data

**Spatial Indexing Requirements:**

- GIST indexes on all geography columns for spatial queries
- Date indexes on `sun_window` table for temporal queries
- Proper PostGIS geometry types (EPSG:4326 for coordinates)

### Migration Tools

**Recommended Tools:**

- Supabase SQL Editor for manual schema creation
- Migration scripts for automated schema deployment
- `pg_dump` for schema export from Azure PostgreSQL
- `psql` for schema import to Supabase
