## Dev Notes

### Architecture Alignment

This story migrates the database schema from Azure PostgreSQL to Supabase while maintaining all PostGIS spatial capabilities. This is critical for preserving the spatial query functionality that SunnySeat depends on for patio search and sun calculations.

### Previous Story Dependencies

**From Story 6.1:**

- Next.js project setup with Supabase client integration
- Environment variables configured for Supabase connection

### Technical Implementation

**Database Architecture:**

- Supabase (PostgreSQL with PostGIS)
- Connection pooling via Supabase connection pooler
- Row Level Security (RLS) if needed
- Custom Postgres functions for spatial queries

**Schema Migration Approach:**

- Export schema from Azure PostgreSQL: `pg_dump --schema-only --no-owner --no-privileges -h <azure-host> -U <user> -d <database> -f schema.sql`
- Review Entity Framework migrations in `src/backend/SunnySeat.Data/Migrations/` for complete schema definition
- Use Supabase SQL Editor or migration scripts in `infrastructure/supabase/migrations/`
- Adapt schema for Supabase (remove Azure-specific settings, adjust connection strings)
- Verify PostGIS functions match current usage patterns (check `src/backend/SunnySeat.Data/` for PostGIS usage)

**PostGIS Validation:**

- Test spatial queries before data migration
- Document any differences in PostGIS versions
- Verify spatial accuracy with sample queries

**Spatial Indexing:**

- GIST indexes on all geography columns
- GIST indexes on all geometry columns
- Verify spatial query performance

### Key Database Tables

**Core Tables to Migrate (from `SunnySeatDbContext`):**

- `venues` - Restaurant/café locations with basic metadata (geometry column: `location`)
- `patios` - Specific patio geometries with spatial data (geometry column: `geometry`, FK: `venue_id`)
- `buildings` - Building footprints for shadow calculations (geometry column: `polygon`)
- `sun_windows` - Precomputed sun exposure time windows (FK: `patio_id`, date indexes)
- `weather_slices` - Weather data for confidence calculations (timestamp indexes)
- `feedback` - User accuracy feedback data (FK: `venue_id`)
- `admin_users` - Admin authentication users
- `venue_quality_metrics` - Venue quality tracking
- `precomputed_sun_exposures` - Precomputed exposure data
- `precomputation_schedules` - Background job schedules

**Source:** Entity Framework configuration in `src/backend/SunnySeat.Data/SunnySeatDbContext.cs`

**Spatial Indexing Requirements:**

- GIST indexes on all geography columns for spatial queries
- Date indexes on `sun_window` table for temporal queries
- Proper PostGIS geometry types (EPSG:4326 for coordinates)

### Migration Tools

**Recommended Tools:**

- Supabase SQL Editor for manual schema creation
- Migration scripts for automated schema deployment
- `pg_dump` for schema export from Azure PostgreSQL
- `psql` for schema import to Supabase
