## Dev Notes

### Architecture Alignment

This story migrates the React frontend to Next.js, adapting components to Next.js Server/Client Component patterns while maintaining all existing functionality.

### Previous Story Dependencies

**From Story 6.5:**

- Spatial/Geographic API endpoints migrated
- API routes working correctly
- Supabase integration established

### Technical Implementation

**Next.js Component Patterns:**

- Use Server Components by default
- Use Client Components when needed for interactivity
- Server Components for data fetching
- Client Components for user interactions

**Component Structure:**

```
/components
  /server           # Server Components
  /client           # Client Components
  /shared           # Shared components
```

**Routing Migration (from `src/frontend/public/src/pages/`):**

- Migrate from React Router (`react-router-dom`) to Next.js App Router
- Current routes to migrate:
  - `/` → `/app/page.tsx` (HomePage - patio search)
  - `/patios/:id` → `/app/patios/[id]/page.tsx` (PatioDetailPage)
  - `/about` → `/app/about/page.tsx` (AboutPage)
- Use `/app` directory for routes
- Configure route structure following Next.js App Router conventions

**State Management:**

- Adapt Context API to Next.js patterns
- Adapt TanStack Query to Next.js
- Use Server Components for initial data
- Use Client Components for interactive state

**MapLibre GL JS:**

- Maintain existing MapLibre GL JS integration
- Adapt map components to Next.js
- Ensure map works in Client Components

### Server vs Client Components

**Server Components (Default):**

- Data fetching from Supabase
- Static content
- No interactivity needed
- Better performance

**Client Components:**

- User interactions
- State management
- Browser APIs
- Event handlers

### Routing Structure

**Next.js App Router:**

```
/app
  /(routes)         # App Router pages
    /page.tsx       # Home page
    /patios
      /page.tsx     # Patios listing
      /[id]
        /page.tsx   # Patio details
```

### State Management Approach

**Context API:**

- Adapt to Next.js patterns
- Use in Client Components
- Provide context from Server Components when possible

**TanStack Query:**

- Adapt to Next.js
- Use with Server Components for initial data
- Use with Client Components for mutations

### MapLibre GL JS Integration

**Map Components:**

- Must be Client Components (browser API)
- Maintain existing map functionality
- Adapt to Next.js patterns
- Ensure map works correctly

### Performance Optimization

**Server Components:**

- Use Server Components for data fetching
- Reduce client-side JavaScript
- Improve initial page load

**Client Components:**

- Only use when needed
- Minimize client-side code
- Optimize bundle size
