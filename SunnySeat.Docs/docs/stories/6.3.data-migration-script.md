## Dev Notes

### Architecture Alignment

This story migrates all actual data from Azure PostgreSQL to Supabase after the schema has been migrated in Story 6.2. This ensures complete data continuity with zero data loss.

### Previous Story Dependencies

**From Story 6.2:**

- Supabase database schema created and validated
- PostGIS extension enabled and verified
- All tables, indexes, and constraints in place

### Technical Implementation

**Migration Strategy:**

- Use `pg_dump` for export from Azure PostgreSQL
- Use `psql` for import to Supabase
- Test with small dataset first
- Validate spatial data with PostGIS functions
- Create backup before migration

**Data Export (respecting foreign key order):**

```bash
# Export in dependency order to respect foreign keys
pg_dump --data-only --column-inserts \
  --host=<azure-host> \
  --dbname=<database> \
  --username=<user> \
  --file=export.sql \
  --table=venues \
  --table=buildings \
  --table=patios \
  --table=admin_users \
  --table=weather_slices \
  --table=sun_windows \
  --table=precomputed_sun_exposures \
  --table=precomputation_schedules \
  --table=venue_quality_metrics \
  --table=feedback
```

**Data Import (Supabase connection string format):**

```bash
# Use Supabase connection pooler URL format
psql "postgresql://postgres.[project-ref]:[password]@aws-0-[region].pooler.supabase.com:6543/postgres" \
  --file=export.sql
```

**Note:** Import order matters for foreign keys. Tables with no dependencies first (venues, buildings), then dependent tables (patios → sun_windows, feedback).

**Spatial Data Validation:**

- Use PostGIS functions to validate spatial data
- Test spatial queries on migrated data
- Verify geometry/geography columns are correct

**Foreign Key Handling:**

- Import data in correct order to respect foreign keys
- Disable foreign key checks during import if needed
- Re-enable and validate foreign keys after import

### Data Validation Approach

**Row Count Validation:**

- Compare row counts for each table
- Verify counts match exactly

**Sample Data Validation:**

- Select random samples from each table
- Compare data values between source and destination
- Verify data types and formats match

**Spatial Data Validation:**

- Test spatial queries on migrated data
- Verify geometry/geography columns contain valid spatial data
- Test PostGIS functions on migrated spatial data

**Relationship Validation:**

- Verify foreign key relationships are maintained
- Test joins between related tables
- Verify referential integrity

### Rollback Procedure

**If Migration Fails:**

1. Keep Azure PostgreSQL backup intact
2. Document what was migrated before failure
3. Restore Supabase to clean state if needed
4. Fix issues and retry migration
