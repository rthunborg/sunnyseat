## Dev Notes

### Architecture Alignment

This story migrates all PostGIS-dependent endpoints that handle spatial and geographic queries. These are critical for SunnySeat's core functionality (patio search, sun calculations, geographic data).

### Previous Story Dependencies

**From Story 6.4:**

- Core API routes migration pattern established
- Supabase client integration working
- API route structure in place

### Technical Implementation

**Spatial Query Migration:**

- Create Postgres functions for complex spatial operations
- Use `.rpc()` for custom spatial operations
- Convert PostGIS spatial queries to Supabase RPC calls
- Test spatial accuracy thoroughly

**PostGIS Functions:**

- Create custom Postgres functions for spatial operations
- Use Supabase RPC to call custom functions
- Test PostGIS functions execute correctly

**Spatial Query Examples:**

```typescript
// Patio search within radius
const { data } = await supabase.rpc("search_patios_nearby", {
  lat: latitude,
  lng: longitude,
  radius_meters: radius,
});

// Sun calculation with spatial data
const { data } = await supabase.rpc("calculate_sun_exposure", {
  patio_id: patioId,
  timestamp: timestamp,
});
```

**Performance Optimization:**

- Ensure spatial indexes (GIST) are utilized
- Monitor query performance
- Optimize queries if needed
- Target: <200ms p95 response time

### Key Spatial Endpoints to Migrate

**Patio Search:**

- `/api/patios` - Search patios by location and radius
- Uses PostGIS `ST_DWithin` or similar for spatial search

**Sun Calculations:**

- Sun exposure calculation endpoints
- Shadow modeling endpoints
- Uses PostGIS spatial calculations

**Geographic Data:**

- Geographic data endpoints
- Location-based queries
- Uses PostGIS geographic functions

### Custom Postgres Functions

**Spatial Functions to Create (based on current API usage):**

- `get_patios_near_point(lat double precision, lng double precision, radius_meters double precision)` - Search patios within radius (replaces `IPatioRepository.GetPatiosNearPointAsync`)
- `calculate_sun_exposure(patio_id integer, timestamp timestamp)` - Calculate sun exposure (replaces `ISunExposureService.CalculatePatioSunExposureAsync`)
- `calculate_batch_sun_exposure(patio_ids integer[], timestamp timestamp)` - Batch sun exposure calculation
- `get_shadow_geometry(building_id integer, timestamp timestamp)` - Get shadow geometry for buildings
- Functions should use PostGIS `ST_DWithin`, `ST_Distance` for spatial operations

**Source:** Check `src/backend/SunnySeat.Core/Services/` and `src/backend/SunnySeat.Core/Interfaces/` for current spatial query patterns
