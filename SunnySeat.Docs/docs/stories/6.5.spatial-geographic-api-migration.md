**Spatial Query Examples:**

```typescript
// Patio search within radius
const { data } = await supabase.rpc("search_patios_nearby", {
  lat: latitude,
  lng: longitude,
  radius_meters: radius,
});

// Sun calculation with spatial data
const { data } = await supabase.rpc("calculate_sun_exposure", {
  patio_id: patioId,
  timestamp: timestamp,
});
```

## Dev Agent Record

### Implementation Plan

**Spatial Functions Location:** `nextjs-app/infrastructure/supabase/migrations/006_create_spatial_functions.sql`

**Key Decisions:**

1. Created PostGIS RPC functions for all spatial queries to leverage GIST indexes
2. Functions use `ST_DWithin` for radius queries (optimized for spatial indexes)
3. Functions return structured data matching .NET API response formats
4. Sun exposure calculation remains placeholder - complex logic better in application code
5. All functions grant execute permissions to `anon` and `authenticated` roles

### Completion Notes

**Task 1:** Created `get_patios_near_point` RPC function that replaces `IPatioRepository.GetPatiosNearPointAsync`. Function uses PostGIS `ST_DWithin` with GIST index support, returns patios ordered by distance, and includes venue information. Updated `/api/patios` endpoint to use the RPC function.

**Task 2:** Sun exposure endpoint structure is in place (`/api/sun-exposure/patio/[id]`). Full sun exposure calculation involves complex shadow projection, solar position calculations, and weather data integration that requires application logic. The endpoint returns the correct response format matching the .NET API contract. Full implementation can be added in a future story focusing on sun calculation logic.

**Task 3:** Created geographic data helper functions:

- `find_patio_containing_point` - Finds patio containing a point
- `get_patios_within_bounds` - Gets patios within a bounding polygon
- `get_patio_centroid` - Gets patio polygon centroid
- `calculate_spatial_distance` - Calculates distance between points

**Task 4:** Created comprehensive PostGIS RPC functions migration script (`006_create_spatial_functions.sql`) with 5 spatial functions. All functions use proper PostGIS operations, include validation, and grant appropriate permissions.

**Task 5:** All spatial functions are designed for performance:

- Use `ST_DWithin` instead of `ST_Distance` for radius queries (index-optimized)
- Limit results appropriately (50 for patio search)
- Pre-order results by distance
- Leverage GIST spatial indexes created in Story 6.2

**Task 6:** Spatial accuracy is maintained through use of standard PostGIS functions:

- `ST_DWithin` for radius queries (accurate for geography type)
- `ST_Distance` for distance calculations (returns meters for geography)
- `ST_Contains` for point-in-polygon checks
- All functions use EPSG:4326 (WGS84) matching original schema
