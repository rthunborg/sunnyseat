# Story 7.1: "Build to Sell" Strategic Roadmap Implementation Plan

## Status

📋 **Planning**

## Overview

**Strategic Goal:** Shift focus from short-term ad revenue to building long-term asset value. Prove Product-Market Fit (willingness to pay) and build a Proprietary Data Moat (verified seating database) to position the app for future acquisition.

**Approach:** PWA-first (Progressive Web App) with Swish payment integration. Single codebase deployable to web and app stores.

## Priority Order (Recommended)

1. **Phase 1: PWA Foundation** - Enable app store distribution
2. **Phase 2: Data Moat (Epic 2)** - Build proprietary verified database
3. **Phase 3: B2B Proof (Epic 3)** - Demonstrate B2B revenue potential
4. **Phase 4: Premium Monetization (Epic 1)** - Add paid features with Swish

## Phase 2: Data Moat (Epic 2)

### Goal

### Story 7.2.1: Automated OSM Ingestion Pipeline

**As a** developer,  
**I want** a script that fetches restaurant nodes from OpenStreetMap with outdoor seating,  
**so that** we can automatically populate the database with candidate venues.

#### Acceptance Criteria

1. Script can query Overpass API for restaurants with `outdoor_seating=yes` in a target city
2. Results are parsed and stored as "Candidate" venues (Blue Dots)
3. Script supports configurable city bounding boxes
4. Duplicate detection prevents adding same venue twice
5. Script is idempotent (can run multiple times safely)
6. Error handling for API rate limits and failures
7. Logging for monitoring ingestion progress

#### Tasks / Subtasks

- [ ] **Task 1: Overpass API Integration** (AC: 1, 6)

  - [ ] Research Overpass API query syntax for `amenity=restaurant` + `outdoor_seating=yes`
  - [ ] Create `OsmIngestionService` class
  - [ ] Implement Overpass API client with rate limiting
  - [ ] Handle API errors and retries
  - [ ] Add request timeout handling

- [ ] **Task 2: City Configuration System** (AC: 3)

  - [ ] Create city configuration file/table (e.g., `cities.json` or DB table)
  - [ ] Define bounding box format (minLat, maxLat, minLon, maxLon)
  - [ ] Add Gothenburg as initial city
  - [ ] Design system to easily add new cities (Stockholm, etc.)
  - [ ] Document configuration format

- [ ] **Task 3: Data Parsing & Transformation** (AC: 2)

  - [ ] Parse Overpass API JSON response
  - [ ] Extract venue name, coordinates, address
  - [ ] Map OSM tags to Venue entity fields
  - [ ] Handle missing or incomplete data gracefully
  - [ ] Validate coordinate data

- [ ] **Task 4: Database Integration** (AC: 2, 4, 5)

  - [ ] Add `VerificationStatus` enum to Venue entity (Candidate, Verified)
  - [ ] Create database migration for verification status field
  - [ ] Implement duplicate detection (by coordinates or OSM ID)
  - [ ] Create repository method to insert/update candidates
  - [ ] Ensure idempotent operations (upsert logic)

- [ ] **Task 5: Ingestion Script/Endpoint** (AC: 1, 5, 7)

  - [ ] Create CLI script or API endpoint for running ingestion
  - [ ] Accept city parameter
  - [ ] Add progress logging
  - [ ] Return summary (venues found, added, skipped)
  - [ ] Make script executable and document usage

- [ ] **Task 6: Testing & Validation** (AC: 4, 5, 6)

  - [ ] Test with Gothenburg bounding box
  - [ ] Verify duplicate detection works
  - [ ] Test idempotency (run twice, no duplicates)
  - [ ] Test error handling (invalid city, API failure)
  - [ ] Validate data quality of ingested venues

#### Technical Notes

- Overpass API endpoint: `https://overpass-api.de/api/interpreter`
- Query example: `[out:json][timeout:25];(node["amenity"="restaurant"]["outdoor_seating"="yes"]({{bbox}}););out;`
- Store OSM node ID in Venue entity for future reference
- Consider using Supabase Edge Function or Next.js API route for ingestion
- Rate limit: Overpass API has usage limits, implement delays between requests

#### Database Schema Changes

```sql
-- Add verification status to venues table
ALTER TABLE venues ADD COLUMN "VerificationStatus" INTEGER NOT NULL DEFAULT 0;
-- 0 = Candidate (Blue Dot), 1 = Verified (Red Dot)

-- Add OSM reference (optional but useful)
ALTER TABLE venues ADD COLUMN "OsmNodeId" BIGINT;
CREATE INDEX "IX_venues_OsmNodeId" ON venues("OsmNodeId");
```

#### Dependencies

- None (can start immediately)

```sql
-- Create venue confirmations table
CREATE TABLE venue_confirmations (
    "Id" SERIAL PRIMARY KEY,
    "VenueId" INTEGER NOT NULL REFERENCES venues("Id"),
    "IpHash" VARCHAR(64) NOT NULL, -- SHA-256 hash of IP
    "UserAgent" VARCHAR(500),
    "CreatedAt" TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP,
    UNIQUE("VenueId", "IpHash") -- Prevent duplicate confirmations
);

CREATE INDEX "IX_venue_confirmations_VenueId" ON venue_confirmations("VenueId");
CREATE INDEX "IX_venue_confirmations_CreatedAt" ON venue_confirmations("CreatedAt");
```

-- Create purchases table
CREATE TABLE purchases (
    "Id" SERIAL PRIMARY KEY,
    "SessionId" VARCHAR(255) NOT NULL, -- Or UserId if you have user accounts
    "SwishTransactionId" VARCHAR(100) UNIQUE NOT NULL,
    "Amount" DECIMAL(10, 2) NOT NULL,
    "Status" VARCHAR(50) NOT NULL, -- 'pending', 'paid', 'failed', 'cancelled'
    "CreatedAt" TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP,
    "UpdatedAt" TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX "IX_purchases_SessionId" ON purchases("SessionId");
CREATE INDEX "IX_purchases_SwishTransactionId" ON purchases("SwishTransactionId");
CREATE INDEX "IX_purchases_Status" ON purchases("Status");

-- Create premium status table (or add to existing user table)
CREATE TABLE user_premium_status (
    "Id" SERIAL PRIMARY KEY,
    "SessionId" VARCHAR(255) UNIQUE NOT NULL, -- Or UserId
    "IsPremium" BOOLEAN NOT NULL DEFAULT false,
    "PurchaseId" INTEGER REFERENCES purchases("Id"),
    "ActivatedAt" TIMESTAMP WITH TIME ZONE,
    "ExpiresAt" TIMESTAMP WITH TIME ZONE, -- For "Season Pass", could be end of season
    "CreatedAt" TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP,
    "UpdatedAt" TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX "IX_user_premium_status_SessionId" ON user_premium_status("SessionId");
