# Story File Audit

After generating a per-story file, run this seven-point self-audit 
against the file you just wrote. Do not mark the story as 
ready-for-dev until all seven checks pass or have been explicitly 
waived by the human operator.

## The Seven Checks

### 1. ACs preserved verbatim from epics.md

Open epics.md and find the story's acceptance criteria. Copy-paste 
compare, not summarize. Check for:
- Same count of ACs
- Same wording (no paraphrasing, no dropped phrases)
- Same formatting (Unicode arrows, code formatting, lists)

If any AC was paraphrased or reformatted, restore the original.

### 2. Design gate criteria preserved or absence noted

Frontend stories should have four design gate criteria: Visual, 
Behaviour, Animation, Visual validation. If epics.md has them, 
copy them verbatim. If epics.md does not have them (e.g. 
infrastructure stories, backend-only stories), add an explicit 
callout near the ACs:

> **No Design Gate Criteria for this story.** [Reason]. This is 
> intentional per epics.md.

Do not bury this in dev notes — it must be visible near the ACs.

### 3. Task list sequencing is correct

Review task order against dependency chains:
- Install dependencies before using them
- Configure tooling before using it in downstream tasks
- Create CSS variables (fonts, tokens) before referencing them in 
  Tailwind @theme or component styles
- Create context providers before the components that consume them

If any task depends on something a later task creates, reorder.

### 4. No invented requirements

Every task should map to an AC from epics.md, or be explicitly 
marked as "Supporting infrastructure, not a direct AC" with a 
brief justification.

Tasks without AC references or infrastructure notes are red flags — 
they indicate the SM is adding scope that wasn't in the epic.

### 5. File impact list is realistic

The "Files Created" section should include:
- All new source files the story will create
- Tool-generated files (components.json, postcss.config.mjs, etc.)
- Any config files needing creation

Add a "Files Modified" section if the story touches existing files:
- package.json (deps, scripts)
- Config files being extended
- Any existing source file the story modifies

Note explicitly any files that might be expected but are NOT created 
(e.g. "tailwind.config.ts is NOT created — Tailwind v4 uses CSS-first 
@theme").

### 6. Doc references include all relevant primary sources

At minimum, every story's References section should include:
- `AGENTS.md` (root project instructions)
- `project-context.md` (design + screen map)
- `_bmad-output/planning-artifacts/epics.md` (source of truth for 
  the story's ACs)
- `nextjs-app/docs/design/DESIGN.md` (for any frontend story)
- `_bmad-output/planning-artifacts/architecture.md`
- `_bmad-output/planning-artifacts/ux-design-specification.md` (for 
  any frontend story)

Additional references as relevant (e.g. UX spec sections, specific 
architecture subsections, Figma file URL).

### 7. Test gate matches the actual state of the project

Check AGENTS.md for any pre-scaffold or transitional notes that 
affect which test commands work. If the story is in a transitional 
phase (e.g. Story 1.1 which installs its own test infrastructure), 
the test gate section must distinguish phases:

**During implementation:** which commands work
**Before marking as review:** which commands must pass

If the project is past any transitional phase, the test gate is the 
standard four commands: typecheck, lint, unit tests, E2E tests.

## What to do if checks fail

Fix the story file immediately, do not defer. A story with audit 
failures is a story the dev agent will misinterpret, leading to 
wasted implementation time or worse — a "completed" story that 
missed its actual requirements.

After fixing, re-run the audit on the corrected file. Only when 
all seven checks pass, mark the story as ready-for-dev in 
sprint-status.yaml.

## Reporting format

When reporting audit results to the human operator, use the 
compact table format:

| Criterion | Status | Fix Applied |
|-----------|--------|-------------|
| ACs preserved verbatim | ✓ / ✗ | [what was fixed] |
| Design gate criteria | ✓ / ✗ | ... |
| Task sequencing | ✓ / ✗ | ... |
| No invented requirements | ✓ / ✗ | ... |
| File impact list | ✓ / ✗ | ... |
| Doc references | ✓ / ✗ | ... |
| Test gate | ✓ / ✗ | ... |

End with "All checks pass, story ready for dev" or "N issues found, 
awaiting your review before marking ready-for-dev."
