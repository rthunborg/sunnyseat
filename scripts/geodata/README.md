# SunnySeat Shadow Caster Geodata Pipeline

This tracked pipeline promotes the local prototype from `building_geodata/goteborg-open/tools/` into a repeatable maintainer workflow for Story 3.0.3. It creates reviewable artifacts for the Story 3.0.2 `shadow_casters` contract. It does not write to Supabase by default.

## Inputs

Raw inputs stay under `building_geodata/`, which is intentionally gitignored.

- Footprints: `building_geodata/byggnad_kn1480.gpkg`
- Baskarta 3D building linework: `building_geodata/goteborg-open/raw/baskarta/shp-extract/byggnad_l`
- DTM tiles:
  - `building_geodata/goteborg-open/raw/hojdmodell-2022/hojdmodell_2022_639_14.zip`
  - `building_geodata/goteborg-open/raw/hojdmodell-2022/hojdmodell_2022_640_14.zip`

The default MVP bbox is explicit and configurable:

```text
EPSG:3007 x=140000..150000, y=6390000..6410000
```

CRS handling is explicit:

- Source footprint CRS: `EPSG:3006`
- Metric processing CRS: `EPSG:3007`
- Runtime geometry CRS: `EPSG:4326`

The derivation uses pyproj `Transformer.from_crs(..., always_xy=True)`. WGS84 runtime geometry is the largest polygon part from the source footprint.

## Commands

Run from the repository root in PowerShell.

```powershell
python scripts/geodata/shadow_caster_pipeline.py derive
python scripts/geodata/shadow_caster_pipeline.py validate
python scripts/geodata/shadow_caster_pipeline.py filter
python scripts/geodata/shadow_caster_pipeline.py emit-import
python scripts/geodata/shadow_caster_pipeline.py validate-artifacts
python scripts/geodata/shadow_caster_pipeline.py emit-spot-check-template
python scripts/geodata/shadow_caster_pipeline.py evaluate-spot-checks
```

Or run the full local pipeline:

```powershell
python scripts/geodata/shadow_caster_pipeline.py run-all
```

All large generated outputs default to `building_geodata/goteborg-open/derived/` and remain gitignored.

## Conservative Filtering

Runtime starts conservatively:

- Include rows become `active = true`.
- Review rows are mapped inactive.
- Excluded rows are emitted as inactive diagnostics and can be omitted from DB import.
- Active rows must be `filter_decision = include`, `height_m >= 3`, and `caster_class = building`.

Existing prototype rules are preserved:

- Exclude heights below 3 m.
- Exclude tiny/tall suspicious records: area `< 25 m2` and height `> 15 m`.
- Exclude extreme height above 80 m.
- Exclude extreme Z spread above 60 m.
- Review very tall records, single-line tall estimates, large Z spread, no-roof-contour material heights, and limited line support.

Story 3.0.3 adds the MVP default for low-quality small `Komplementbyggnad` records:

```text
objectType = Komplementbyggnad
areaM2 < 20
qualityScore <= 0.65
```

These records are excluded with reason `small-komplementbyggnad-low-quality`.

## Import Handoff

`emit-import` writes import-ready JSONL mapped to the Story 3.0.2 `shadow_casters` shape. It also writes `shadow_casters.import_handoff.sql`, which uses psql client-side `\copy`. Do not use PostgreSQL server-side `COPY FROM '/local/path'` against Supabase because that reads from the database server filesystem.

Before a manual import, review:

```powershell
python scripts/geodata/shadow_caster_pipeline.py validate-artifacts
```

Then run the generated SQL manually with a local `psql` client and an approved Supabase connection string. Do not commit connection strings or secrets.

The generated SQL includes smoke checks:

- row counts by `filter_decision` and `active`
- active rows below 3 m
- active review/exclude rows
- invalid geometry
- missing source dataset
- sample `get_buildings_near_point(57.7089, 11.9746, 200)` query

## Spot-Check Gates

Story 3.0.4 adds a deterministic, no-database QA gate for cluster-scoped building-shadow confidence. It covers these launch clusters inside the MVP EPSG:3007 bbox: Inom Vallgraven, Nordstan, Lilla Bommen, Avenyn, Vasastan, Haga, Linné, and surrounding central areas.

Generate a manual observation template from the current import JSONL:

```powershell
python scripts/geodata/shadow_caster_pipeline.py emit-spot-check-template
```

The default template writes `building_geodata/goteborg-open/derived/shadow_caster_spot_checks.template.jsonl`. It emits 10 rows per launch cluster, at least 70 central rows total, and includes all required sun-condition buckets per cluster:

- `morning_low_angle`
- `midday_high_sun`
- `afternoon_evening_directional`

Each spot-check row has a stable JSONL schema:

- `spot_check_id`
- `cluster_id`
- `cluster_name`
- `point_type` (`venue` or `street_facing`)
- `coordinate_wgs84` with `lon` and `lat`
- optional `venue_slug` and `venue_name`
- `sun_condition_bucket`
- `representative_local_datetime`
- `expected_building_shadow`
- `observed_manual_result`
- `agreement_result` (`pending`, `agree`, `disagree`, or `uncertain`)
- `uncertainty_causes`
- `notes`
- `reviewer`
- `source_artifact`
- `reviewed_at`

Copy the template to `shadow_caster_spot_checks.results.jsonl` after manual review and fill in the observation fields. Pending template rows deliberately leave `expected_building_shadow` blank; before a row is completed, replace the placeholder coordinate with a real venue or street-facing observation point, record the building-shadow expectation, record the manual observation, and point `source_artifact` at traceable local evidence. Generated spot-check evidence and local observation files remain under `building_geodata/` and are not production imports.

Completed rows are validated before they count toward the gate:

- `spot_check_id`, `source_artifact`, and `representative_local_datetime` are required.
- Coordinates must stay inside the MVP bbox and the declared cluster radius.
- `agreement_result` must match `expected_building_shadow` versus `observed_manual_result`.
- Duplicate `spot_check_id` values fail validation.
- Uncertainty causes are allowed only with `agreement_result: "uncertain"`.

Use `agreement_result: "uncertain"` for checks affected by unmodelled obstructions instead of counting them as building-data failures. Supported uncertainty causes are:

- `tree`
- `awning`
- `umbrella`
- `bridge`
- `temporary_structure`
- `seasonal_furniture`
- `other` (requires a note)

Evaluate completed observations:

```powershell
python scripts/geodata/shadow_caster_pipeline.py evaluate-spot-checks
```

The evaluator writes:

- `building_geodata/goteborg-open/derived/shadow_caster_cluster_validation.json`
- `building_geodata/goteborg-open/derived/shadow_caster_cluster_validation.md`

Pass/fail semantics:

- A cluster is `insufficient_evidence` until it has at least 10 completed venue or street-facing checks and all three sun-condition buckets.
- The central set fails until it has at least 70 completed checks.
- A cluster is `eligible` only when the full central set has at least 70 completed checks, the cluster has at least 10 completed checks, at least 9 clear building-agreement checks after uncertainty rows are separated, and building-data agreement is at least 85%. This concrete threshold is inside the ADR's "about 85-90%" range and keeps the gate conservative while avoiding a false precision claim.
- A cluster is `blocked` when evidence is sufficient but building-data agreement is below 85%.
- Uncertainty causes are summarized separately from the building-data agreement denominator.
- `--no-require-all-clusters` is for fixture or partial diagnostics only; it always writes a failing partial-scope report and must not be treated as the launch gate.

Review/quarantine shadow-caster rows remain inactive until approved by spot-check evidence. This tooling only emits gate artifacts; it does not update runtime confidence scoring, write to Supabase, or change live DB rows. Story 3.0.5 consumes `shadow_caster_cluster_validation.json`, especially `cluster_id`, `status`, `checkedCount`, `agreementRate`, `missingConditions`, `uncertaintyCounts`, and `evidenceFiles`.

## Tests

Compile scripts:

```powershell
python -m py_compile scripts/geodata/shadow_caster_pipeline.py
```

Run no-network unit tests:

```powershell
python -m unittest discover -s scripts/geodata/tests
```

The tracked fixtures in `scripts/geodata/testdata/` prove one include row, one review row, one excluded row, one eligible spot-check cluster, one insufficient-evidence spot-check cluster, and one blocked/low-agreement spot-check cluster.
